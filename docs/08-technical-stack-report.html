1. 项目总览

股市锦囊是 Windows 上的规则型桌面辅助工具。个股分析读取行情与历史日线，再给出理由、风险及仓位参考；全市场选股先按快照筛选和排序，再对入选股票做深度分析。自选持仓、横向对比、条件预警与按需资金流查询围绕这两条流程展开。

计算在本机完成，真实行情按需联网。程序没有交易账户、下单服务或自动学习模型。五档强度改变的是解释规则的宽严程度，不会改变已经测量到的数据，也不保证未来收益。

当前 GUI 是 src/qt_app/ 的 PySide6 Widgets；旧 Tkinter 生产层已经移除。各层直接位于 src/，导入如 domain.engine。src/version.py 保存产品版本，历史截图或文章日期不能替代它。

3. 架构与数据流

输入代码 / 选择预设
  → 页面校验与控制器开始任务
  → BoundedMarketDataProvider → BoundedUrllibProvider → urllib
  → workflow 编排：解析结果、识别取消或降级
  → engine.measure()：客观 Measurement
  → policy.decide()：当前档位的 Decision
  → 当前任务的结果回 GUI：表格、概览、详情、图表

全市场入口先做 apply_filters() 与 rank()，可再对 TopN 复用个股分析。业务计算不依赖控件，数据源通过 Protocol 合同传入，所以测试可以用 FakeProvider。Qt 网络组件是可讨论的替代方向，当前生产 provider 使用的是有界 urllib 传输。

切档只对缓存测量重判，不重新获取行情。数据还是原来那一批；若要最新行情，应重新开始取数。更多见第 01 篇与第 05 篇。

5. 行情数据：缺失、失败与取消分开

实时行情按东方财富、新浪顺序尝试；历史日线还包括腾讯前复权和普通日线；全市场快照使用东方财富 clist；资金流是独立的 fflow 查询。网络失败可在剩余预算内换源，解析或输入错误应明确退出，不能假设所有错误都值得重试。

快照证券市场号来自 f13，不能单靠代码前缀构造 secid。缺失字段记 None，负 PE 可以是有效原始值。若个股涨跌幅无效但最新价与昨收价有效，则从两者重算；无效价格不能伪装成零价。

历史不可用时允许明确标注降级；用户取消历史请求则应终止分析。分页少取一部分时要说明「非全市场结果」；资金流不可用只影响它自己的查询。完整解析、金额转换与配置说明见第 06 篇。

6. 策略：测量与解释分开

测量包括均线、趋势、动量、量能、日内位置、布林位置、支撑压力和波动八因子，再汇总风控扣分。每个因子带人能读懂的理由。MA 是窗口平均；EMA 给新数据更高权重；MACD 比较快慢 EMA；RSI 比较近期涨跌幅度；ATR 考虑日内高低和跳空。公式及不足样本行为见第 02 篇。

五档分别为稳健、稳进、标准、积极、激进。标准档买入线为 +25、卖出线为 −25，其余档位改变门槛、风险权重、确认要求、风险预算和仓位上限。所有档位买入都要求有效的正把握程度，稳健与稳进还要求更高确认。光谱是同一份测量的五种解释，不是五次独立预测。

把仓位公式落到一个小例子

L3、价格 20 元、ATR 2.5%、把握程度 80、决策分 45、本金 10 万元：止损距离为 1.8 × 2.5% = 4.5%；乘入强度与把握系数后，理论投入约 14.5%。按本项目 100 股单位向下取整为 700 股，成本 14000 元，所以实际投入为 14%。止损参考价 19.10 元，对应测算亏损 630 元。

理论比例与整手后的实际比例并不相等。参考价不代表真实成交价，也没有自动执行止损；费用、跳空和流动性可能使实际损失更大。

回测逐日只用当时及之前的历史生成信号。SELL 命中看原始价格收益是否小于 0，不能因扣费而把平盘算成卖对；BUY/HOLD 命中看扣费后收益是否为正。各组平均收益扣除成本，基线是观察窗口原始收益的平均值，不是账户净值曲线。总样本够用也不代表每类信号样本都充足。

7. 界面：信息、几何与状态一起检查

五个页签是个股分析、全市场选股、自选／持仓、条件预警、个股资金流。QTableView 配 QStandardItemModel，表头排序改变视觉顺序而保留模型行号；排序键与显示值需要同步更新。K 线由 domain/chart 的纯几何配合 QPainter 绘制，鼠标悬停显示当根 OHLC。共享颜色来自 tokens.json，红表示涨／买，绿表示跌／卖。

窄窗下，卡片标题和说明允许换行，表单与按钮分行，检查实际内容是否超出滚动视口。清空要阻止迟到结果回填；切档要同步概览、表格与详情。建议仓位数值 30 的单位已是百分数，应显示为 30%，不能再次乘 100。

控制器按批次和代次管理异步结果；BacktestController 在后台按需回测，并缓存本批次同一标的与档位的报告。快速切换只保留一项在跑和一项最新等待选择；换批或清空使缓存失效，改本金不重跑回测。具体验收见第 04 篇和窄窗与状态检查。

快捷操作包括当前页开始分析／选股（Ctrl+Enter、F5）；个股页有清空（Ctrl+L）和复制详情（Ctrl+Shift+C）。自选载入个股页只填输入，不自动取数；查看当前标的资金流会切到资金流页并查询。预警需手动开启监控，默认 60 秒轮询且仅程序运行时生效。

8. 测试：证明行为，不背诵数字

指标测试用可手算样例，provider 测试模拟成功与失败，编排用 FakeProvider，Qt 测试检查真实控件、排序、取消与装配。测试数量以当次发现和执行结果为准；离线自检通过不能证明行情接口当前可用，headless 测试也不能替代真实 Windows 字体和缩放检查。

9. 打包：交付整个应用目录

scripts/build_exe.py 调用 PyInstaller；构建中间产物留在 build/，最终应用在 dist/股市锦囊/，含 EXE、Qt 动态库、插件与资源。不能只拿走 EXE。Windows 交付物在 Windows 构建，运行命令见README。

随后在同一构建环境运行 scripts/make_release_manifest.py，生成组件清单、第三方声明、许可证副本和完整文件摘要，再加 --verify 验证。当前构建未签名；正式发布还需完成发布验收条件。

onedir 是 ADR-0004 的项目决定，依据包括启动测量和可替换 Qt 库的分发方案。钉住构建依赖有助于复现，但仍需核对环境、文件清单、许可证、SBOM 与第三方通知。打包自检检验基础可执行性，真实 GUI 和联网行为另行验收。

src/ui/manual.py 生成 dist/使用说明.html，其中既有从代码取得的常量，也有需要维护的操作文字。生成一次不能自动保证所有说明准确；它与 docs/ 教材各有测试和审阅责任。

10. 防御性设计与边界

容易误解的事实际边界
输入控件有范围就够了单个范围不能证明上下限顺序正确；领域入口仍需校验非法、缺失和非有限值。
有取消标记就能立即停协作取消要在各可中断点检查；不能强行终止正在执行的系统调用，关窗仍需管理线程生命周期。
设置改了就一定保存了读取损坏配置回退默认；写入失败返回失败状态，内存设置与持久化成功不同。
CSV 加引号就安全了字段还需中和电子表格公式注入，保留正确转义与免责声明；中文导出使用 UTF-8 BOM。
样例数据能代替失败查询样例仅供离线验证或明确演示。空态说明下一步，失败态说明原因，不制造看似真实的结论。

当前配置只在本机保存，没有多设备同步；图表以日线为主，回测是单股信号复盘；资金流按需查询，不进入核心评分。扩展这些能力需要新的需求与验证，不能只在教材里先宣布实现。

11. 学习路线

  1. 先看数据模型与金额表示，学会区分价格、比率、数量和缺失值。
  2. 读测量、决策与回测，用一个小例子手算，再与行为测试对照。
  3. 沿 provider → workflow → controller → page 追踪一轮结果，检查取消、失败和迟到结果。
  4. 看 Qt 布局、表格与自绘，按正常和窄窗、成功和空／失败状态分别验收。
  5. 最后读工程门禁与交付，从具体证据判断检查了什么、还有什么没有验证。

教学内容集中于 docs/，工程合同与证据留在 loop/，许可证留在 licenses/，生成说明书的程序留在 src/ui/manual.py。本篇负责解释与导航，详见资料职责表。
