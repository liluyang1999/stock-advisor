05 · 线程、取消与世代守卫

GUI 线程为什么碰不得网络、迟到结果如何丢弃、协作取消与总 deadline

← 首页 · ← 上一篇：本项目的界面实现

一条铁律：QWidget 只能在 GUI 线程碰

Qt 的控件不是线程安全的。在工作线程里直接 label.setText(...) 可能当场崩溃，也可能"看起来能跑"然后在用户机器上偶发崩溃——后者更糟，因为它不可复现。

所以本项目的并发边界是死的：

GUI 线程          │  工作线程（QThreadPool）
──────────────────┼──────────────────────────
页面、控件、模型   │  取数、解析、算分
控制器（QObject） │  纯 Python 对象，不碰任何 QWidget
        ▲         │
        └── queued signal ──┘   ← 结果只能这样回来

为什么信号能安全跨线程

Qt 的信号槽在跨线程连接时默认是 queued connection：信号携带的参数被放进目标对象所在线程的 事件队列，由那个线程在自己的事件循环里调用槽函数。于是槽函数体内的代码天然运行在 GUI 线程， 可以安全操作控件。

一个容易踩的坑：把槽连接到临时闭包（lambda）上， 不宜依赖其隐含线程归属。这里把槽写成 GUI 线程里 QObject 的绑定方法，并显式使用排队连接；不要把普通同线程按钮回调与这条跨线程边界混为一谈。

问题一：迟到的结果会覆盖新状态

症状

用户分析股票 A，等得不耐烦，改成分析股票 B。A 的请求还在路上，B 先返回并渲染。 接着 A 姗姗来迟，把界面覆盖成 A 的数据——用户看到的是 B 的股票名配 A 的数据。

解法：世代守卫（Generation Guard）

class GenerationGuard:
    current: int            # 只在 GUI 线程递增
    def bump(self) -> int   # 开新一轮：世代 +1，返回新世代号
    def is_current(self, g) -> bool
控制器 start():
    cancel, gen = self._begin()      # 世代 +1，拿到本轮世代号
    worker = Worker(..., gen, ...)   # 世代号随 worker 走

worker 完成 → 信号回 GUI 线程 → 槽里第一件事：
    if not self._is_current(gen): return   # 上一代的结果，直接丢弃
为什么这个方案是线程安全的：世代计数器只在 GUI 线程读写， worker 只持有一个 int 快照。整个机制不需要锁——把可变状态限制在单线程内， 比加锁更简单也更不容易出错。

取消 ≠ 重启

动作世代是否 +1为什么
用户点「停止」否这一轮仍要交付它的「已取消」终态，好让界面把按钮复位、状态写清楚
用户再次点「开始」是新一轮 supersede 旧一轮，旧结果不再需要

清空与停止也不同：停止仍要接收本轮终态，清空则表示不再展示本轮任何结果；必须防止已排队的结果或完成信号把表格、概览和详情重新填回来。测试应主动交付这些迟到信号，而不是靠等待一段时间猜它们不会出现。

问题二：取消根本停不下来

症状

点了「停止」，界面按钮变灰了，但程序还在跑。关窗时更明显——窗口消失了，进程还赖着不退。

根因：取消只在两次取数「之间」被检查

for symbol in symbols:
    if cancel.is_cancelled(): break   # ← 只有这里检查
    fetch(symbol)                     # ← 这一步本身可能跑 100 秒

早期实现里，单只股票的历史取数最坏要走 4 个数据源 × 3 次重试 × 8 秒 ≈ 100 秒， 且每个源各自重新获得完整的超时预算。这段时间里取消完全不起作用。

解法一：协作取消令牌深入传输层

run_with_contract(attempts, deadline=..., cancel_token=...):
    for label, call in attempts:
        if cancel_token.is_cancelled(): return 已取消
        if deadline.expired():          return 超时
        ...

控制器开一轮时，把本轮的取消令牌绑给自己的 provider，于是令牌一翻，在途请求就会在下一个可中断点退出。

这里有个隐藏前提：每个控制器必须持有自己的 provider 实例。 五个控制器共用一个 provider 时，它的取消令牌是单一可变状态—— 个股页按「停止」会连带翻掉预警轮询和选股在途请求的令牌。这比不做取消更糟。

解法二：总 deadline

@dataclass(frozen=True)
class Deadline:
    budget_seconds: float
    started_at: float
    clock: Callable[[], float] = time.monotonic   # 注入时钟，测试不必真的 sleep
一个 deadline 覆盖所有重试与备用源，而不是每个源重新拿一份完整预算。 当前默认单次取数预算为 20 秒；它不是整个批次或进程退出的绝对时限。阻塞 I/O 仍须在传输层受约束，外层检查不能强杀正在执行的系统调用。time.monotonic 而非 time.time： 单调时钟不受系统时间调整影响。时钟可注入，因此 deadline 相关的测试一秒都不用睡。

问题三：周期任务重叠

条件预警是一个 QTimer 每 60 秒跑一轮。如果某一轮因为网络慢跑了 90 秒会怎样？ 定时器不会等它——第二轮、第三轮照常提交，多个周期重叠在跑。

后果

预警是边沿触发的（条件由假变真才提醒，持续为真不重复刷屏），它靠一个 fired 集合记住 「哪些规则已经响过」。重叠的周期各自拿着同一份旧快照出发，于是同一条预警每轮都会重新触发； 更糟的是它们完成时会互相覆盖 fired 状态。

解法：在途守卫

def _tick(self):
    if self._in_flight:      # 上一轮还没跑完
        return               # 跳过这一拍
    self._in_flight = True
    ...提交 worker...

def _on_cycle_done(...):
    if 不是当前世代 or 已停止: return
    self._in_flight = False  # 当前代这一轮结束，放行下一拍

关闭时的生命周期

closeEvent → 先给所有控制器请求取消
    共用最多 5000 ms 的等待预算
    检查 waitForDone() 返回值
    未排空：保留窗口与 worker 对象，提示正在停止
    通过定时器继续检查，排空后才真正关闭
顺序不能反。不先取消就等待，等的是完整的取数时长； 而 QThreadPool 的析构函数会无限期阻塞直到任务结束——那就是「关不掉的窗口」。

有限等待并不自动证明池已排空；还需核查完成状态、失效代次和对象生命周期。单靠写下 5000 ms，不能保证任意阻塞请求都能在五秒内结束。

如何测试并发代码

回测也要离开 GUI 线程

BacktestController 只读取已经取得的历史日线，不持有 provider、不联网。它保留一项正在计算的工作和一项最新等待选择；快速切换标的或档位时不把每次点击都排成队。

报告按本批次的「规范化标的 + 档位」缓存，最多保存 150 项；换批或清空时清缓存并递增代次。纯函数 backtest_steps 每处理一个历史样本便让出控制权，worker 在样本之间检查取消；领域内核不依赖 Qt 或线程。旧计算即使正在结束，迟到报告也不再交付。修改本金只影响仓位，不影响回测。测试应覆盖缓存命中、最新等待选择、换批作废和当前选择匹配。

要验证的性质怎么写成确定性测试
迟到结果被丢弃手工构造两轮，让第一轮的完成信号在第二轮开始之后才发，断言界面状态属于第二轮
取消交付「已取消」终态取消后等待完成信号，断言终态标志而不是断言"没有信号"
deadline 生效注入假时钟，手工推进时间，断言超时分支——不 sleep
取消真的到达传输层用 spy provider 记录被绑上来的令牌，断言 cancel() 后它确实被翻转
跨控制器不误伤取消 A，断言 B 的令牌未被翻转
并发测试的通用原则：不要用 sleep 来"等一等"。 sleep 让测试变慢，而且在慢机器上偶发失败（flaky）。 正确做法是注入可控的时钟、用事件循环等待信号、 把并发点做成可观察的对象（世代号、令牌、在途标志）然后直接断言它们。

本篇要点回顾

  • QWidget 只能在 GUI 线程操作；结果靠 queued signal 回来，槽用绑定方法不用闭包。
  • 世代守卫丢弃迟到结果；计数器只在单线程读写，因此无需加锁。
  • 协作取消 + 总 deadline让"停止"和"关窗"真的能停下来；每个控制器要有自己的 provider。
  • 周期任务需要在途守卫，否则边沿触发的状态会被重叠周期反复重置。
  • 关闭顺序是先取消、再有限等待；测试并发用假时钟而不是 sleep。
