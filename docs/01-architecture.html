01 · 分层架构与依赖方向

纯领域内核、端口与适配器，以及「让机器守住架构」这件事

← 回到知识库首页

为什么先讲架构

这个项目的所有其它设计——为什么能离线自检、为什么换 GUI 框架不用重写算法、为什么测试跑得飞快—— 都是同一个决定的推论：把「算什么」和「怎么显示、从哪取数」彻底分开。 先把这层讲透，后面几篇会省力很多。

四层结构

src/
  domain/        ← 纯领域内核（12 个模块）：只依赖标准库，不许 import 网络与 GUI
  data/          ← 数据适配：唯一做网络请求的地方
  services/      ← 编排：把 domain 的纯函数按业务流程串起来
  qt_app/        ← PySide6 界面：页面、控制器、部件、主题
  ui/            ← 与框架无关的展示层（格式化、文案、主题 token、说明书 HTML）
  observability/ ← 结构化日志
  ports.py       ← 传输层的「端口」合同（envelope / deadline / 取消）
  version.py     ← 版本号唯一真源

依赖只能单向流动

qt_app  ──▶ services ──▶ domain
   │            │            ▲
   │            └──▶ data ───┘
   └──▶ ui（展示层，纯函数）

箭头是允许的依赖方向。反向依赖一律禁止：domain 不知道 services 存在， 更不知道有没有界面。这条规则不是靠自觉——它由静态门禁 G-CORE 在每次提交前用 AST 扫描强制。

核心概念：纯领域内核（Pure Domain Core）

定义：src/domain/ 下的 12 个模块只能 import 标准库。 不许 import urllib（不碰网络）、不许 import PySide6（不碰界面）、不做文件 I/O。 它们是一堆纯函数：同样的输入永远得到同样的输出，没有隐藏状态。

这样做换来什么

好处具体表现
可独立单测测 RSI 不需要启动 Qt、不需要联网、不需要造 mock。传一个数组进去比对结果即可。
测试快870 个测试跑完约 50 秒，其中大部分是 Qt 界面测试；纯算法测试几乎不耗时。
换框架不动算法本项目真的把界面从 Tkinter 全量换成了 PySide6（ADR-0001）。领域内核一行没改。
可离线自检--self-test 用内置样例数据跑通整条管线，不联网、不开窗，用来验证交付物是否可用。

Qt 是应用的依赖，不是模型的依赖

这句话是本项目的一条硬性约束。整个程序运行期只有一个第三方依赖 PySide6，但即便如此， 领域内核连它也不许 import。原因很直接：一旦某个算法模块 import PySide6， 它就再也不能在没有 Qt 的环境里被测试或复用，「纯内核」就名存实亡了。

怎么强制：loop/scripts/check_core_boundaries.py 解析每个核心模块的 AST， 提取全部 import 目标，与 core-module-manifest.json 里声明的 forbidden_import_roots 比对。写错一行，G-CORE 门禁立刻变红。

为什么用 AST 而不是文本 grep：grep 会被字符串、注释、以及 importlib.import_module("PySide6") 这类写法骗过去；AST 看的是语法结构。

端口与适配器（Ports & Adapters）

src/ports.py 定义传输层的合同，而它自己不依赖任何具体传输—— 既不 import urllib，也不 import PySide6。于是「用 urllib 同步取数」和「用 Qt 的 QNetworkAccessManager 异步取数」两种实现可以满足同一份合同，合同本身还能离线确定性测试。

三个不可绕过的性质

性质含义为什么重要
错误分类每次失败归入 network / parse / validation 等固定类别日志里能统计「到底是网断了还是对方改了字段」
总 deadline一个预算覆盖所有重试与备用源否则 4 个源 × 3 次重试 × 8 秒 ≈ 100 秒，界面像卡死
零伪造回退失败的信封结构上不带 data 字段调用方在类型层面就拿不到假数据

信封（Envelope）模式

@dataclass(frozen=True)
class TransportOutcome[T]:
    succeeded: bool
    data: T | None = None            # 只有成功才有
    completeness: Completeness = ... # 分页完整度
    error_class: ErrorClass | None = None
    message: str = ""
    cancelled: bool = False          # 取消 ≠ 失败
    attempts: tuple[str, ...] = ()   # 试过哪些源

关键在 ok() 和 failed() 两个构造器：failed() 根本不接受 data 参数。 这就是「零伪造」的机器保证——不是靠程序员记得别返回假数据，而是失败路径压根构造不出带数据的结果。

取消为什么要单独一个字段？如果取消也走「抛异常」，它和超时长得一模一样， 界面只能笼统说「获取失败」。有了 cancelled 标志，用户主动取消一次全市场筛选时， 程序能如实说「已取消」而不是报错——这是两件完全不同的事。

测量与决策分离

这是领域内核里最值得单独讲的一个设计。

engine.measure(quote, history)  ──▶  Measurement   # 客观测量，与档位无关
policy.decide(measurement, level) ──▶ Decision      # 按 5 档强度翻译成买/持/卖 + 仓位
measure()decide()
产出RSI、均线关系、波动率、各因子得分……买/持/卖、建议仓位、把握程度
受档位影响否——同一只股票的客观数据不因你保守还是激进而改变是——同样的测量，L1 可能建议观望，L5 建议买入
是否联网否（输入已经取好了）否
这个切分换来一个直接的用户价值：切换决策强度档位时，程序只对缓存的 Measurement 重新跑一次 decide()，不重新联网。 用户点 L1→L5 是瞬间响应的，而且不会消耗一次取数配额。

包结构的两次演进

架构不是一次定死的。这个项目的 src/ 结构改过两次，两次都留下了 ADR：

决策做了什么动机
ADR-0007把 23 个扁平模块按职责分成 domain/data/services/ui 子包单目录 23 个文件看不出层次；分层后依赖方向才可检查
ADR-0015删掉 src/stock_advisor/ 这层包根，各层直接成为 src/ 下的顶级包src/ 下只有一个子目录属于无意义嵌套；导入从 stock_advisor.domain.engine 缩短为 domain.engine
行为保持的搬迁（behavior-preserving move）是一种独立的工作类型。 这两次重构都遵守同一条纪律：只移动文件、只改 import，不碰任何一行逻辑， 改完后原有测试必须一个不改地全部通过。如果重构时顺手「优化」了逻辑， 测试红了你就无法判断是搬错了还是改错了。

本篇要点回顾

  • 领域内核是纯函数 + 只用标准库，由 AST 静态门禁强制，不是靠自觉。
  • 依赖单向流动：界面 → 编排 → 领域；领域不知道上层存在。
  • 端口定义合同、适配器提供实现；失败信封结构上不带数据，零伪造由类型保证。
  • 测量与决策分离，因此切档不联网。
  • 重构分两类：行为保持的搬迁和真正的行为变更，两者绝不混在一次改动里。
