一、金额为什么不能用 float

这是整个项目最值得单独教的一个知识点，因为它在任何涉及钱的程序里都成立。

>>> from decimal import Decimal
>>> 0.1 + 0.2
0.30000000000000004
>>> Decimal.from_float(2.675)
Decimal('2.67499999999999982236431605997495353221893310546875')

二进制浮点数无法精确表示大多数十进制小数。单次计算误差极小，但累积起来会显示成用户看得见的偏差—— 持仓成本 × 股数 × 若干次加减之后，浮动盈亏可能差出几分钱，而用户会截图来问「为什么算错了」。

本项目的三分法

类别类型例子
金额与报价Decimal，量化到 2 位小数价格、成本、本金、成交额、市值、盈亏
数量int股数、成交量、天数
比率与统计量float涨跌幅%、RSI、MA、ATR%、评分
为什么比率可以用 float：它们本来就是统计量，还要喂给 mean/pstdev 这类函数； 用 Decimal 既慢又没有意义（RSI 精确到小数点后 20 位没有价值）。 关键是明确转换边界：不要先用 float 算出金额再补救。报价进入统计层时转成 float；仓位和止损比率参与金额计算时，经十进制字符串转为 Decimal，再与原始 Decimal 报价运算。

三个实现细节

① 四舍五入要用 ROUND_HALF_UP，不是 Python 默认的银行家舍入

>>> Decimal("0.005").quantize(Decimal("0.01"))                    # 默认 ROUND_HALF_EVEN
Decimal('0.00')      # ← 银行家舍入，0.005 舍成 0.00
>>> quantize_money(Decimal("0.005"))                              # ROUND_HALF_UP
Decimal('0.01')      # ← 金额习惯

② float 转 Decimal 必须先经 repr

Decimal(2.675)          → 2.67499999999999982...  量化后得 2.67   ✗
Decimal(repr(2.675))    → Decimal("2.675")         量化后得 2.68   ✓

repr() 给出能往返的最短十进制串，把二进制展开挡在门外。

③ 「安全解析器」的契约是：绝不抛异常

parse_money(None)     → None
parse_money("-")      → None      # 东财用 "-" 表示字段缺失
parse_money("abc")    → None
parse_money(True)     → None      # bool 是 int 的子类，必须显式挡掉
parse_money(float("inf")) → None
parse_money("1E30")   → None      # 超出十进制上下文，也返回 None 而不是抛异常
最后一条是本项目修过的一个真实缺陷：quantize() 写在 try 块外面， 于是超大有限数会抛 decimal.InvalidOperation——而这个函数的文档明明承诺「读不出合法金额就返回 None」。 用户在本金框里输入一个荒谬的大数就会让程序抛异常。 教训：安全解析器的每一条出口都必须真的安全，包括量化这一步。

二、多源回退与解析鲁棒性

数据源

用途源
实时行情东方财富 → 新浪
历史日线东方财富 → 新浪 → 腾讯（前复权）→ 腾讯
全市场快照东方财富 clist（分页）
个股资金流东方财富 fflow（多主机轮换）

市场号不能靠代码前缀猜

东财接口要求 secid 形如 1.600000（沪）或 0.000001（深/北）。 很多教程教人「6 开头是沪、0/3 开头是深」——这在北交所出现后就错了（新代码段是 920xxx）。 本项目从快照返回的 f13 字段直接取市场号，而不是猜。

这是全市场快照的处理方式。用户手动输入六位代码时，symbols.py 仍要按所支持的代码规则规范化；两种入口不能混为一谈。

解析必须容忍缺失与异常值

情形处理
字段是 "-"记 None，不记 0
PE 为负（亏损股）合法值，照常保留
字段整个不存在None
区间过滤遇到 None若该端设了边界 → 判不通过（宁可漏，不可错）

个股报价的涨跌幅若无效，会在最新价和昨收价有效时按 (最新价 − 昨收价) / 昨收价 × 100 重算。比如 11 元对 10 元是 10%，不是缺失值或 0%；价格本身无效时不能靠这个公式编出行情。

生产路径使用 BoundedMarketDataProvider 适配 BoundedUrllibProvider 的结果。网络类失败可在剩余预算内换源，解析或输入合同错误会停止，不是遇到任何错误都无限重试。

三、零伪造（Zero Fabrication）

核心主张：接口失败必须明确报错，绝不伪造行情或建议。 一个投资辅助工具如果在取不到数据时返回 0 或上一次的缓存值假装成功， 用户会基于不存在的数据做决定——这比直接报错危险得多。

三层落地

层怎么保证
结果合同TransportOutcome.failed() 不接受 data 参数，返回 data=None；仍需调用方检查成功标志和数据，不能仅靠类型提示判断真实有效
编排层取数失败返回带错误的结果对象，不返回默认值；历史取不到时明确标记为「降级」并把原因写进风险提示
界面层失败行照样占位、数值格显示破折号、失败原因可读全文

取消不是历史缺失：历史请求因数据不可用而失败时，可以给出带明确提示的降级分析；若用户已取消，编排应直接终止，不再计算或交付一份「降级成功」。这能避免停止后仍出现新的结论。

四、分页完整度：一个隐蔽而危险的坑

症状

全市场快照要分页拉取（每页 100 条，最多 100 页，受 20 秒总预算约束；按股票代码稳定排序）。如果第 3 页失败了会怎样？ 早期实现是 break 掉循环、返回已经拿到的部分——然后若无其事地拿去排序选股。

用户以为自己在全市场里选股，其实只在拿到的那一部分里。 界面上没有任何提示，因为程序自己都不知道数据是残缺的。

解法：把完整度当成一等公民带回来

@dataclass(frozen=True)
class Completeness:
    expected: int | None        # 应有多少条
    received: int | None        # 实收多少条
    missing_pages: tuple[int, ...]   # 缺了第几页

    @property
    def is_complete(self) -> bool: ...

成功的信封带着这份完整度一路回到界面，选股结果会如实标注「非全市场结果」并说明缺了哪几页。

本项目踩过的一个「链路断在最后一米」的教训： 完整度机制早就实现好了，但出货用的 provider 没有实现 market_completeness() 这个方法， 而编排层用 duck-typing 取它——取不到就默认「完整」。于是整套机制在出货版里从未生效过， 警告永远不会触发。

教训：能力做好了不等于用户拿得到。本项目后来加了一道装配级门禁（G-SURFACE）： 凡是声明已交付的能力，都必须能从装配好的主窗口往下找到对应的部件，否则构建失败。

五、数据摄取的边界防护

防护防什么
响应体字节上限超大响应（或被篡改的响应）把内存撑爆
总 deadline慢速滴流（slow drip）攻击，以及正常的慢网拖死界面
请求头按当前适配器设置 User-Agent 等字段；这不保证公开接口持续可用，失败仍需如实报告
失败分类把 network / parse 分开，日志里能看出是网断了还是对方改了字段

六、持久化

%APPDATA%\StockAdvisor\config.json    ← 自选/持仓、本金、档位、预设、预警规则
%APPDATA%\StockAdvisor\logs\          ← 结构化日志（NDJSON，每行一条）

原子写

1. 写进同目录的临时文件
2. flush + fsync            ← 把文件缓冲提交给操作系统与存储设备
3. os.replace(临时文件, 目标)  ← 同一文件系统内的原子替换

原子替换避免正常并发读取时看到半份 JSON，文件同步减少崩溃造成的数据丢失；这不是对任意断电或设备故障的绝对保证。读取失败或损坏时回退默认配置；保存失败返回 False，当前内存设置不等于已经落盘，应检查页面提示。

测试绝不能写用户的真实 %APPDATA%。 本项目用环境变量 STOCK_ADVISOR_CONFIG 把配置路径指向临时文件， 并写了一条测试断言「只有应用装配处才能调用读真实配置的那个入口」—— 因为曾经真的有测试把档位写进了开发者自己的配置里。

七、结构化日志

{"timestamp":"2026-07-21T13:29:59.383+09:00","level":"INFO",
 "logger":"stock_advisor.fund_flow","message":"资金流完成",
 "operation":"fetch_fund_flow","outcome":"ok"}
规则原因
只写声明过的字段，未登记字段直接报错防止把敏感信息随手塞进日志
原始报文、完整自选股/持仓不入日志那是用户的隐私数据
打包成无控制台的 GUI 后，轮转文件是唯一可诊断的持久 sink用户看不到 stderr

本篇要点回顾

  • 金额用 Decimal、数量用 int、比率用 float；金额运算中的比率须显式转换。
  • 四舍五入用 ROUND_HALF_UP；float→Decimal 必须过 repr。
  • 「安全解析器」的每条出口都要真的安全，包括量化那一步。
  • 市场号取自接口字段，不靠代码前缀猜。
  • 零伪造由结果合同（失败时 data=None）+ 编排 + 界面共同守护；取消时停止计算。
  • 分页残缺必须如实上报；能力做好了不等于用户拿得到，要有装配级门禁兜底。
  • 配置原子写 + fsync；日志只写白名单字段。

本轮补齐的边界

日线日期使用 YYYY-MM-DD，计算前升序排列；完全相同的重复日合并，同日冲突拒绝。备用源涨跌幅也按这个顺序重算。有效样本少于30条会明确降级。详情与导出记录来源及获取时间；获取时间不是交易所报价时间。全市场接口报告总数但有效价格记录较少时，仍显示不完整，不能把被过滤的缺失行情伪造为零。
