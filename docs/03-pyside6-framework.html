PySide6 是什么

PySide6 是 Qt 官方的 Python 绑定（项目名 Qt for Python），把 C++ 写的 Qt 6 暴露给 Python。绑定代码由 shiboken6 自动生成——所以安装 PySide6 一定会带上它。

对比项PySide6PyQt6
维护方Qt 公司官方第三方 Riverbank
本项目的许可取舍采用 LGPL 分发方案，保留库替换能力及许可材料未选用；不能把 PySide6 的分发方案直接套用到其它绑定
API都映射 Qt 概念，但信号定义、类型和对象生命周期细节须逐项验证，不能只换 import 就认定迁移完成

本项目把许可证与分发方式一起考虑：选择 PySide6，并以保留独立 Qt 动态库的应用目录分发。 教材解释项目的选择，许可证原文与完整分发要求留在 licenses/ 和工程记录中（见 07 · 测试、门禁与交付）。

三个包名别搞混

  • PySide6-Essentials —— 核心模块：QtCore / QtGui / QtWidgets / QtNetwork…（约 200 MB）
  • PySide6-Addons —— 附加模块：QtWebEngine、Qt3D、QtMultimedia、QtCharts…（约 430 MB）
  • PySide6 —— 上面两个的合集（约 634 MB）

本项目只装 Essentials 并钉死 6.12.0。K 线是用 QPainter 自绘的， 不需要 QtCharts。上面的体积是选型时的安装测量，不是压缩包或最终交付物大小；裁剪仍需由构建结果验证。

QObject：对象树与内存

Qt 的基类是 QObject。它给了三样东西：对象树、信号槽、 元对象系统（属性、类型内省）。

对象树解决的是「谁负责销毁谁」：给对象指定 parent，父对象析构时会自动删掉所有子对象。 布局里 addWidget() 会自动认亲，所以界面代码通常不需要手动释放。

Python 开发者最常踩的坑：对象被 GC 掉。 如果一个 QObject 没有 parent，又只被一个临时变量引用，函数返回后 Python 就回收了它—— 界面上那个部件会莫名消失，或者信号连了却永远不触发。
反过来还有一个镜像坑：C++ 侧对象已删除，Python 侧包装还在，再访问就抛 RuntimeError: Internal C++ object already deleted。

本项目的帮助对话框还有明确的关闭路径：结束时从主窗持有列表中移除，再调用 deleteLater()，由事件循环释放控件。反复打开关闭帮助时，应检查对象数量回落；只把窗口藏起来不等于已经释放。

信号与槽：Qt 的解耦方式

信号槽是「发生了什么」与「谁来处理」之间的松耦合连接。发信号的一方不知道谁在听， 也不关心有几个人听。 

class Worker(QtCore.QObject):
    finished = QtCore.Signal(int, object)   # 声明信号及其参数类型

worker.finished.connect(self.on_finished)   # 连接
worker.finished.emit(3, payload)            # 发射

连接类型：跨线程安全的关键

类型行为什么时候用
AutoConnection（默认）同线程→直连；跨线程→排队绝大多数情况
DirectConnection立即在发射方线程执行槽确知同线程且要求同步
QueuedConnection投递到接收方线程的事件队列，稍后执行工作线程 → GUI 线程

默认的 Auto 已经覆盖了跨线程：只要接收方是有线程亲和的 QObject，Qt 会自动排队。 这就是为什么工作线程可以直接 emit，而槽函数在 GUI 线程里安全执行。

接收者必须明确。不要依赖临时 lambda 的隐含执行线程。本项目把跨线程信号连到 GUI 线程里 QObject 的绑定方法槽，并显式使用排队连接；普通同线程按钮回调仍可使用 lambda。

事件循环

app.exec() 启动事件循环：不断从队列里取事件（鼠标、键盘、重绘、定时器、排队的槽调用） 并分发。它是单线程的——所以在槽里做耗时工作，整个界面就卡住。

QTimer 也是事件循环的一部分：timer.timeout.connect(fn) 之后 start(60000)，每 60 秒把一次调用投进队列。本项目的条件预警轮询就是这么驱动的。

信号 vs 事件

  • 事件（event）是 Qt 发给部件的通知，用重写 xxxEvent() 处理， 比如 paintEvent、closeEvent、mouseMoveEvent。
  • 信号（signal）是对象主动广播的「发生了什么」，用 connect 处理。

经验法则：想改变部件自身的行为用事件；想让别人知道用信号。

部件与布局

不要用绝对坐标摆控件——换字体、换 DPI、换语言，版式立刻散架。用布局管理器：

  • QVBoxLayout / QHBoxLayout —— 垂直、水平排列
  • QGridLayout —— 网格
  • QStackedWidget —— 同一位置切换多页（本项目的五页导航用 QTabWidget）

布局里每个部件有尺寸策略（size policy）与拉伸因子（stretch）， 决定空间不够或有余时谁让步、谁伸展。addWidget(w, 3) 里的 3 就是拉伸因子。

模型 / 视图

Qt 把「数据」和「怎么显示」拆开，好处是同一份数据可以有多个视图，而且大数据量时只渲染可见行。

角色常用类说明
模型QAbstractTableModel自己实现 rowCount/columnCount/data，适合大数据或数据本就存在别处
模型（现成）QStandardItemModelQt 自带的通用容器，逐格塞 QStandardItem，写起来快
视图QTableView / QTreeView负责渲染与交互
代理模型QSortFilterProxyModel夹在中间做排序/过滤，会改变行号映射
委托QStyledItemDelegate定制单元格的绘制与编辑

数据角色（ItemDataRole）

同一个单元格可以按不同「角色」存多份数据，这是 Qt 模型的核心设计：

  • DisplayRole —— 显示出来的文本
  • UserRole —— 自定义数据，常用来存排序键或原始对象
  • BackgroundRole / ForegroundRole —— 背景色 / 前景色
  • ToolTipRole —— 悬停提示

「显示 +9.50%、排序按 9.5」正是靠 DisplayRole 与 UserRole 分离实现的—— 按文本排序会得出「+9.50% < -1.20%」这种字面序。

QSS 样式表

语法像 CSS，选择器按类名、对象名或自定义属性：

QPushButton { background: #F4F1EA; border-radius: 4px; }
QPushButton[role="primary"] { background: #1B3A5B; color: white; }
#mainToolbar { border-bottom: 1px solid #DDD; }

属性选择器 [role="primary"] 配合 widget.setProperty("role", "primary")， 就能给同一种部件做出多种外观，而不必派生子类。

两个必踩的坑：
1. 改了 property 之后样式不会自动刷新，要 style().unpolish(w); style().polish(w) 手动重算。
2. 给 QWidget 直接子类设背景色不生效，除非置 WA_StyledBackground 属性——Qt 默认只为 QFrame 这类自带绘制的部件画样式表背景。

自绘：QPainter

现成部件满足不了时（比如 K 线图），重写 paintEvent 自己画： 

def paintEvent(self, event):
    p = QtGui.QPainter(self)
    p.setRenderHint(QtGui.QPainter.RenderHint.Antialiasing)
    p.fillRect(rect, brush)
    p.drawLine(x1, y1, x2, y2)

关键在于把几何计算与绘制分开：算坐标的部分是纯函数，可以脱离 Qt 单测； paintEvent 只负责把算好的坐标画出来。本项目的 K 线就是这么组织的。

并发：不要碰跨线程的控件

Qt 的铁律只有一条：只有 GUI 线程能触碰控件。常用工具：

  • QThreadPool + QRunnable —— 提交一次性任务，池子自动复用线程（本项目用它）
  • QThread —— 需要长期存活、自带事件循环的工作线程
  • 结果回传一律走信号，靠排队连接自动切回 GUI 线程

展开讲见 05 · 线程、取消与世代守卫。

打包与部署

  • PyInstaller 打包时必须带上 Qt 插件目录：platforms/（缺了就 「could not load the Qt platform plugin」直接启动失败）、styles/、 imageformats/。
  • QT_QPA_PLATFORM=offscreen 让 Qt 在无显示器环境跑（CI 测试靠它）。 字体效果还受已安装字体与平台插件影响，不能据此保证真实桌面观感；人工验收补用 Windows 原生渲染。
  • 本项目按 ADR-0004 使用 onedir，保留可替换的 Qt 动态库；依赖版本、许可证和第三方通知也要一并核对。
