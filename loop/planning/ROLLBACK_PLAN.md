# 回滚计划

## 原则

- 每个里程碑可单独回滚。
- 领域模型和配置 schema 在 UI 迁移期间保持向后兼容。
- 不使用破坏性 Git 重写；保留用户未提交改动。

## 回滚层级

1. 组件：关闭新 Qt page/worker，恢复上一实现。
2. 入口：main.py 回到最后一个验证通过的 UI 入口。
3. 依赖：恢复精确锁文件和构建脚本。
4. 发布：回退到上一个有哈希和 self-test 证据的 EXE。
5. 配置：只执行向后兼容读取；不得删除未知字段或用户自选/持仓。

## 触发

- P0/P1 缺陷。
- 配置损坏/数据丢失。
- 迟到结果导致错误标的显示。
- Qt 插件/字体在目标机不可用。
- 包体、启动、内存或许可证门禁失败且无批准豁免。

## 演练证据

每个发布候选需记录回滚步骤、产物哈希、配置往返测试和恢复时间。
