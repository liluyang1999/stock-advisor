# 工程规则

## 规格与范围

1. 每项实现必须关联 `REQ-*`、`AC-*` 和 `WI-*`。
2. 高成本或难回滚选择先写 ADR。
3. 变更只解决当前工作项，不顺手重构无关模块。
4. 当前初始化阶段只写 `loop/`；源码迁移需进入已批准工作项。

## 代码与架构

1. 领域对象优先不可变、精确类型、纯函数。
2. Qt 只允许进入 bootstrap、presentation、controller、worker adapter 和 widgets。
3. `data_provider.py` 是唯一网络边界；解析保持纯函数。
4. `store.py` 保持原子写入和测试配置隔离。
5. 不能把旧 `app.py` 逐行翻译成单个巨大 Qt 类。
6. 后台任务使用显式 signals、取消令牌和 generation id；过期结果丢弃。
7. 捕获异常时保留上下文；不得静默吞错。

## 数值与数据

1. 外部输入在边界验证；NaN/Inf 不得穿透到用户输出。
2. 中间计算保留精度，展示层才舍入。
3. 每个指标有单位、范围、样本要求和缺失语义。
4. 排序必须确定；重复运行结果一致。
5. 资金流独立失败，不进入核心决策。

## UI

1. `QApplication` 统一设置 Microsoft YaHei；禁止局部任意字体。
2. 原生标题栏只保留一次图标和“股市锦囊”，内容区不重复身份。
3. 决策强度五档和摘要整体居中；控件尺寸、间距和对齐使用 token。
4. 红绿同时配文字/符号，不仅依赖颜色。
5. 所有主操作有可见焦点、tooltip 和 accessibleName。

## 测试与证据

1. Bug 修复先有复现测试。
2. 禁止删除、跳过或放宽测试只为变绿。
3. PR 不访问公网；使用 FakeProvider 和固定载荷。
4. PySide6 迁移需替代每个 Tk 行为合同，不能只追求测试总数。
5. 命令、退出码、环境和产物路径进入证据索引。
6. 实现者不能独立批准自己的变更。

## 依赖与发布

1. 运行、开发、构建依赖分类并精确锁定。
2. 新依赖先评估许可证、体积、维护性、安全和回滚。
3. 发布只从干净、锁定环境构建。
4. 任何发布、推送、合并或外部写入都要人工门禁。
