This artifact re-captures EVD-LOOP-004 after a final-review fix wave (F1 + F2) landed
on top of the Plan 1 hardening re-baseline that originally created this record (Task 9,

holes found on final review of validate_loop.py's control-plane digest invariant:

F1 - _digest_ok() exempted ANY v2 evidence record with a truthy superseded_by from the
digest check. If every v2 record were (or became) superseded -- or superseded_by pointed
at an id that was never created -- the "recorded baseline matches the tree" guarantee
would hold vacuously, with no live record actually verified against the current digest.
validate_loop.validate() now:
  1. requires at least one evidence record with record_version=="2.0.0", no truthy
     superseded_by, and control_plane_sha256 == control_plane_digest(); absent that, it
     appends "no live v2 baseline evidence matches the current control plane";
  2. requires every truthy superseded_by value to name an id present in the evidence
     index; absent that, it appends "{id} superseded_by references unknown evidence
     {target}".
Both checks are implemented in the new _evidence_baseline_errors() helper (called once,
after the per-record evidence loop, with control_plane_digest() computed exactly once
per validate() call and threaded through _digest_ok() too) and proved in
loop/tests/test_loop_tooling.py::test_live_v2_baseline_is_required_and_supersede_refs_resolve,
which mutates an in-memory copy of the evidence list (never written to disk) to show
both new errors fire, alongside a manual disk mutate-and-revert demonstration (captured
in the task report, not committed -- state/evidence-index.json is unchanged by it).

F2 - the per-row register-schema load in validate_loop.py's JSONL loop
(schemas/<register>.schema.json, for registers/experiments|assumptions|changes|
decisions|waivers.jsonl) read and json.loads'd the schema file unguarded, unlike the
sibling operational-schema load a few lines above. A missing or malformed register
schema file would raise and abort validate() instead of reporting a clean error. It is
now wrapped in the same try/except (OSError, json.JSONDecodeError) as its sibling: on
failure it appends "cannot load register schema {schema_name}: {exc}" and continues
to the next JSONL file rather than raising.
