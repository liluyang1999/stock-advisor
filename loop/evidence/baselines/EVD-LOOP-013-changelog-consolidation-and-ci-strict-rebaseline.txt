LINE-ENDING NORMALISATION (CI-breaking defect found and fixed here)
-------------------------------------------------------------------
.gitattributes declares `loop/** text eol=lf` precisely so control_plane_digest() is
reproducible across checkouts, but loop/scripts/_common.py::atomic_write_json and
render_status.py --write used text mode, which on Windows writes CRLF. Every hash recorded
from this worktree therefore encoded CRLF while git stores LF, so a clean checkout (i.e.
the first real CI run) would have failed twice over:
  * control_plane_digest over LF bytes = 4d58c4ff... vs the CRLF value recorded, and
  * 33 evidence artifacts failing their recorded sha256.
Proven, not assumed: `git show HEAD:<artifact>` bytes hash to a different value than the
worktree bytes, and the recorded sha256 matched the worktree (CRLF) one.
Fixed by (a) passing newline="\n" in both writers, (b) normalising every loop/ file to LF
so the worktree equals git's canonical form, (c) recomputing the affected hashes, and
(d) a new loop test that fails if any loop/ file ever contains CRLF again. Artifact content
is unchanged — only line endings, which git normalises anyway — so this corrects a recording
error rather than rewriting evidence.

JSON FORMAT UNIFIED (generator now matches the files it writes)
---------------------------------------------------------------
`dump_json` wrote "one line per top-level key, compact values" and justified it with "state/*.json
are all hand-written in that shape". That premise was false: `atomic_write_json` only ever writes
state/backlog.json and state/current.json, and current.json — like every large human-reviewed
control file (work-items.json 1169 lines, quality-gates.json 363, capability-surface.json 202,
tokens.json 317) — is indented. So the next `update_state.py --write` would have flattened
current.json 83 -> 25 lines, burying a two-line semantic change, and `--check` (semantic compare)
would never have warned. The compact shape also puts a whole array on one line, so appending one
evidence record rewrites that entire line — the worst possible diff granularity.

Fixed by making `dump_json` emit `indent=2` + trailing newline (the majority convention) and
reformatting state/backlog.json once (9 -> 51 lines, nested arrays now expand). The schemas/ and
templates/ files keep their compact shape — they are static and never pass through this function.
`test_generator_written_json_round_trips_byte_for_byte` now asserts, for every file the generator
writes, that re-serialising its content reproduces it byte for byte; it failed on current.json
before the change and passes after, so generator/file agreement can no longer drift unnoticed.
