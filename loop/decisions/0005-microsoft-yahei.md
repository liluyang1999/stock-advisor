# ADR-0005：全局字体采用 Microsoft YaHei

- 状态：accepted
- 日期：2026-07-10
- 决策来源：用户明确要求

## 背景

用户明确要求全局字体统一为 Microsoft YaHei（对应 REQ-016）；REQ-033 同时要求字体缺失时必须可见失败或使用文档化回退，不能静默错字体渲染。PySide6 迁移引入独立的字体解析路径（`QFont`/`QFontInfo`），如果不在迁移早期把字体合同钉死为一条明确 ADR，不同页面/组件很容易在开发过程中各自选择系统默认字体或平台差异字体，导致 RISK-008（Microsoft YaHei/DPI/长中文导致字体 fallback 或裁切）在开发后期才被发现，返工成本更高。

## 决策

所有应用可控制的可见文字统一使用 `Microsoft YaHei`，包括 QWidget、菜单、tooltip、对话框、表格、图表、自绘文字和 HTML 说明书。创建 `QFont("Microsoft YaHei")` 后用 `setPointSizeF()` 设置小数点字号，在 QApplication 级应用，并由 QFontInfo 验证实际字体。Windows 原生标题栏字体由操作系统控制，是唯一明确例外。

## 字号

caption 9pt、body/control 10.5pt、section 13pt、page 17pt；任何辅助文字不低于 9pt。

## 替代方案

1. **使用 Qt/Windows 系统默认字体（如 Segoe UI 或平台默认无衬线字体，拒绝）**：跨平台一致性更好、无需显式设置，但不满足用户明确指定 Microsoft YaHei 的要求，且中文字符渲染效果、字重与现有 Tkinter 基线观感不一致。
2. **应用内打包字体文件并强制加载（拒绝）**：可以保证目标机器无论是否安装该字体都能渲染一致，但打包商业字体文件涉及未经评估的字体许可问题，且违反"不得打包系统字体文件"的边界。
3. **（采用）声明式统一使用 `Microsoft YaHei` 并由 `QFontInfo` 校验实际生效字体，缺失时显式失败或回退**：见"决策"。

## 后果

正面：所有页面/组件字体表现统一，避免不同开发者各自选择字体造成的视觉不一致；`QFontInfo` 校验让"实际使用了哪种字体"可在测试中断言，不必依赖人工目视检查。

负面 / 成本：目标平台限定 Windows 字体可用性；不得打包系统字体文件。若字体缺失，发布前失败并明确环境要求，不能静默使用其他字体后仍宣称通过。

## 回滚

只有用户批准新的字体合同才可修改。

## 重访触发

高 DPI 截断通过布局/token 修复，不用缩小字号规避（即 DPI 裁切本身不构成重新评审字号的理由）。若目标 Windows 环境不再预装 Microsoft YaHei、用户提出新的品牌字体要求，或 REQ-033 的回退字体文档需要更新为不同字体，才需要重新评审本决策。
